내부용 · FICC S&T 주제: AI 에이전트 입문 난이도: 입문 도구: Claude

업무 하나,
에이전트에게 맡겨보기

반복되는 업무 하나를 골라, Claude Code 같은 실행 환경을 내 업무에 맞게 설정하고 활용하는 다섯 단계를 다룬다. 특정 업무보다 적용 방법에 초점을 맞추며, 02·03단계에는 직접 따라 할 수 있는 가상 자료와 지시서 예시를 담았다.

예시

이메일 정리, 회의록에서 할 일 추리기, 여행 일정 정리처럼 형식이 어느 정도 정해져 있고 반복되는 업무부터 시작한다.

배경

지금의 에이전트가 다른 이유

챗지피티로 검색이나 글 요약만 해봤다면, 에이전트에게 업무를 어디까지 맡길지 판단하기 어려울 수 있다. 모델의 추론 능력이 발전하고, 파일을 읽고 쓰거나 명령을 실행하는 도구와 작업 규칙을 연결하는 실행 환경(harness)이 갖춰지면서 에이전트의 활용 범위가 넓어졌다. 필자는 부서 업무 자동화와 DART 스크리닝 로직 점검부터 웹툰·영상 콘텐츠 제작, 개인 기록을 정리하는 세컨드 브레인까지 여러 분야에 이 방법을 적용해왔다. 이 글도 에이전트를 활용해 CLAUDE.md에 정리한 말투 체크리스트로 점검한다. 이 학습문서에서는 업무 하나를 골라 에이전트에게 맡기고 결과를 확인하는 과정을 직접 경험한다.

챗봇과 에이전트의 차이. 일반적인 챗봇 사용은 질문을 입력하고 답변을 받는 방식이다. 에이전트는 "예약 확인 메일들을 읽어서 여행 일정표 파일로 정리해줘"처럼 맡기면, 어떤 파일을 볼지 스스로 정하고, 하나씩 읽고, 결과를 다시 파일로 쓰는 여러 단계를 이어서 진행한다.

예전과 지금. 답변만 제공하는 챗봇을 사용할 때는 사람이 답을 업무 시스템이나 메신저, 엑셀에 옮기고, 오류가 생기면 다시 질문해야 했다. 에이전트는 연결된 도구를 사용해 결과를 파일이나 시스템에 반영하고, 실행 중 발생한 오류를 확인해 수정하는 과정까지 이어간다. 파일과 명령을 다루는 실행 환경이 다양해지면서, 개발자가 아닌 사람도 자연어로 작업을 맡기는 방식으로 활용하고 있다.

여기서 말하는 ‘에이전트 만들기’. 이미 제공되는 모델과 Claude Code 같은 실행 환경을 활용한다. 여기에 지침으로 작업 규칙을 정하고, 스킬로 업무 절차를 재사용하며, 필요할 때 MCP로 도구와 데이터를 연결한다. 기존 실행 환경을 내 업무에 맞게 설정하는 데 집중한다. 에이전트 내부에서 돌아가는 처리 과정이나 아키텍처를 밑바닥부터 개발하는 법은 다루지 않는다.

팀원에게 업무를 맡기듯 지시서를 쓰고, 결과를 확인하며 수정한다. 에이전트가 잘 처리하는 작업은 맡기는 범위를 넓히고, 어려워하는 작업은 작게 나누거나 중간 확인 절차를 둔다. 작업의 특성에 맞춰 맡길 범위와 확인 방법을 조정한다.

잘 쓴다는 것의 기준. 기능의 수나 구조의 복잡성보다 실제 업무의 불편을 얼마나 줄였는지로 판단한다. 주어진 조건 안에서 반복 작업을 줄이고, 사람이 판단해야 할 부분을 구분할 수 있다면 업무에 맞게 활용하고 있는 것이다.

이 학습문서를 마치면 남는 것

  • 업무 하나를 "에이전트에게 맡길 수 있는 형태"로 쪼개는 방법
  • Claude에게 역할·형식·금지사항을 구체적으로 지시하는 요령
  • 결과물을 확인하고 지시서를 고치는 반복 작업
  • 다른 업무로 확장할 때 무엇부터 볼지에 대한 기준
  • AI에게 맡겨도 되는 일과 사람이 정해야 하는 일을 구분하는 기준
Claude, Claude Code, Claude Cowork가 궁금하다면

Claude는 Anthropic이 제공하는 AI다. 모델이 파일을 읽고 쓰거나 명령을 실행하려면 해당 기능을 수행하는 도구와 실행 환경이 필요하다. Claude Code와 Claude Cowork는 이런 도구를 모델에 연결해 작업을 수행하는 실행 환경이다. Claude Code는 터미널을 중심으로 작업하고, Claude Cowork는 터미널 없이 작업을 맡기는 방식을 제공한다. OpenAI의 Codex도 모델과 도구를 연결해 작업하는 코딩 에이전트다. 이런 실행 환경에 스킬·MCP·지침을 더해 업무에 맞게 활용한다. 도구의 기능과 가격은 바뀌므로, 실제로 맡길 업무에 적용해보고 선택한다. 이 학습문서는 교육에서 사용하는 Claude를 기준으로 설명한다.

활용 과정 · 5단계

내 업무에 맞게 에이전트를 활용하는 과정

기존 실행 환경을 바탕으로 업무 하나를 에이전트에게 맡기고, 결과를 확인하는 다섯 단계다. 각 단계는 이전 단계의 결과물을 이어받으며, 실행과 확인 과정에서 필요한 부분을 수정한다.

01
관찰
맡길 업무 찾기

하루 업무를 시간대별로 적어본다. 그중 "반복적이고 형식이 정해져 있으며 시간이 드는" 일을 골라내고 작게 쪼개본다.

업무를 나눌 때는 판단이 필요한 부분과, 판단이 끝난 뒤 정해진 형식에 따라 반복해서 처리하는 부분을 구분한다. 이메일 답장이라면 "어떤 내용으로 답할지 정하는 것"과 "그 내용을 문장으로 옮겨 쓰는 것"으로 나뉘는데, 에이전트에게는 뒤쪽을 먼저 맡기기가 쉽다. 영수증으로 지출 정리, 회의록에서 할 일 뽑기, 읽을 아티클 요약, 여행 일정 정리처럼 매번 비슷한 형식으로 반복되는 일이면 좋은 후보다.

구분이 어렵다면 Claude에게 업무 내용을 설명하고, 판단이 필요한 부분과 반복해서 처리할 부분을 나눠달라고 요청한다. 제안한 구분과 그 이유를 검토한 뒤 사람이 맡길 범위를 정한다.

완료 기준: 반복해서 처리할 부분과 사람이 판단할 부분을 구분했고, 이번에 맡길 작업의 범위를 정했다.

02
설계
목표·입력·출력 한 장으로 정리하기

01단계에서 먼저 맡기기로 한 작업을 "무엇을 받아서 무엇을 내놓는지"로 명확히 쓴다. 신입 사원에게 업무를 맡길 때 전달할 지시서를 작성한다고 생각한다. 어떤 자료를 입력으로 받을지, 결과를 어떤 형식·분량·말투로 작성할지, 지켜야 할 금지사항은 무엇인지 적는다.

이렇게 정리한 지시서를 파일로 저장해두면 다음번에는 매번 새로 쓰지 않고 불러와 쓸 수 있다. Claude Code에서는 이런 지시서를 스킬로 구성해 재사용하고, Claude Projects에서는 프로젝트 지침으로 활용한다. 프로젝트 지침은 해당 프로젝트의 대화에 적용하고, 스킬은 필요한 작업에서 불러온다. 적용 방식은 다르지만, 업무 절차를 정리해 반복해서 사용한다는 목적은 같다.

지정한 폴더에서 위 예약 확인 메일과 메모 파일들을 찾아 읽고, 위 규칙에 따라 itinerary.md로 일정표를 작성하세요.

지시서가 이렇게 구성되는 이유. "정리해줘"라는 요청만으로는 원하는 형식과 분량을 전달하기 어렵다. 위 지시서는 역할, 출력 규칙, 금지사항을 나눠 적어 어떤 기준으로 작업해야 하는지 구체적으로 전달한다.

완료 기준: 어떤 자료로 무엇을 만들지 구체적으로 적었고, 실행할 때 지켜야 할 규칙까지 정리했다.

03
실습
Claude Code로 에이전트 체험하기

이번 단계에서는 지시서에 대한 답변을 받는 데서 나아가, 에이전트가 직접 파일을 다루게 한다. 업무에 필요한 자료를 폴더 하나에 모으고, 같은 폴더에서 Claude Code를 실행한다. 지시서를 전달한 뒤 "이 폴더의 자료를 읽고 결과를 파일로 정리해줘"라고 요청한다.

처음에는 실제 업무 폴더가 아니라 자료를 복사해둔 별도 폴더에서 시작한다. Claude Code가 파일을 잘못 수정하거나 삭제해도 원본을 보존하기 위해서다. 결과를 확인한 뒤 필요한 파일을 실제 업무 폴더로 옮긴다. 삭제나 외부 전송처럼 되돌리기 어려운 동작은 실행 전에 사람이 한 번 더 확인하는 습관을 들인다.

모델이 파일을 읽고 쓰거나 명령을 실행할 때는 연결된 도구를 사용한다. Claude Code와 Claude Cowork 같은 실행 환경은 모델에 도구와 작업 규칙을 연결해 요청한 일을 수행하도록 돕는다.

Claude Code가 파일 목록을 확인하고 자료를 읽은 뒤 결과 파일을 만드는 과정을 살펴본다. 결과에서 부족한 부분을 찾아 지시서를 수정하고, 같은 자료로 다시 실행한다. 실습에 사용할 자료가 없다면 아래의 가상 자료를 활용한다.

04
검증
결과를 확인하는 습관 들이기

AI는 만능이 아니다. 형식이 정해진 반복 요약이나 데이터 정리는 에이전트에게 맡겨도 되지만, 투자 판단이나 고객에게 나가는 최종 문구, 컴플라이언스 확인처럼 판단이 필요한 일은 사람이 정한다. 이런 업무에서는 에이전트가 초안을 작성하고, 사람이 내용을 확인해 사용 여부를 판단한다.

업무에 따라 틀린 정보 한 줄의 대가가 클 수 있는 만큼, 에이전트 결과물 중 숫자·날짜·고유명사처럼 반드시 원문과 대조해야 할 항목을 표시하는 습관을 만든다. 애매한 표현은 사람이 판단해 정리하고, 출처가 불명확한 문장은 근거를 확인한 뒤 다시 작성하게 한다.

정확성뿐 아니라 지시서에 적은 항목이 결과에 빠짐없이 들어갔는지, 원문에 없는 내용을 새로 지어내지 않았는지, 정해둔 파일명과 형식을 지켰는지도 함께 확인한다. 정확성·완전성·근거성·형식을 점검하는 기준은 다른 업무에도 적용한다.

필요하면 Claude에게 결과물을 정답 예시나 이전 업무 결과와 비교하고, 차이와 그 이유를 설명해달라고 요청한다. 비교 결과를 바탕으로 초안을 보완하되, 최종 확인과 사용 여부는 사람이 판단한다.

완료 기준: 핵심 정보의 정확성, 빠진 내용, 근거, 출력 형식을 확인했고, 해결하지 못한 항목은 따로 표시했다.

05
확장
다른 업무로 넓히기

지시서와 실행 결과를 동료에게 보여주고 피드백을 받는다. 그다음 다른 반복 업무나 아직 맡기지 않은 작은 작업 중 하나를 다음 실습 대상으로 정한다.

이메일, 회의록, 문서 등 입력 자료의 형태가 비슷한 업무부터 고른다. 기존 지시서에서 재사용할 부분과 수정할 부분을 나누고, 작은 범위부터 적용한다. 판단이 많이 필요한 업무는 작업 범위와 확인 방법을 더 구체적으로 정한 뒤 시도한다.

이후에는 반복해서 쓰는 지침을 CLAUDE.md 파일로 저장하거나, 필요한 도구와 데이터를 MCP로 연결하는 방식으로 확장한다. CLAUDE.md는 Claude Code가 작업할 때 참고하는 지침 파일이고, MCP는 외부 도구와 데이터에 접근하는 연결 방식이다. 반복 작업을 처리하는 스크립트를 Claude Code에 요청하는 방법도 있다. 예를 들어 영수증 폴더에서 매달 지출 요약 파일을 만드는 스크립트를 준비하면, 다음부터는 같은 작업을 스크립트로 실행한다. 이런 확장은 다섯 단계를 경험한 뒤 업무에 필요한 범위에서 시도한다.

완료 기준: 동료에게 결과를 보여주고 의견을 받았으며, 다음 업무에 재사용할 부분과 바꿀 부분을 정했다.

스킬의 핵심도 글로 쓴 지시서다

Claude Code 같은 실행 환경에서 사용하는 스킬의 구성은 Anthropic 공식 저장소에서 확인한다. 문서 작성, PDF 처리, 디자인 등 여러 작업에 사용하는 스킬이 공개되어 있다.

github.com/anthropics/skills↗

저장소의 skills 폴더에서 관심 있는 스킬을 고른 뒤 SKILL.md 파일을 살펴본다. 각 스킬의 핵심 지시사항은 마크다운(.md) 파일에 적혀 있다. 프롬프트를 쓰듯 해야 할 일, 작업 순서, 지켜야 할 규칙과 예시를 글로 정리한다.

앞에서 만든 지시서도 파일로 저장하고 사용 목적과 규칙을 정리해 스킬로 발전시킨다. 에이전트는 필요한 작업에서 이 지시사항을 읽고 따른다. 작업에 따라 실행 스크립트나 참고 자료를 함께 구성한다.
